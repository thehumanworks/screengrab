# screengrab — verification contract

Binary criteria for "done". Each row is checkable with a single command and either passes or fails.

| # | Criterion | Verifiable signal |
|---|-----------|-------------------|
| 1 | Source compiles to a single binary on macOS | `cd screengrab && go build -o screengrab .` exits 0 and produces `./screengrab` |
| 2 | CLI exposes the required flags | `./screengrab --help` exit 0 and stdout contains all of: `--fps`, `--duration`, `--output`, `--mode`, `--display` |
| 3 | Default FPS is sane for AI consumption (≤ 4) | `grep -n "defaultFPS" main.go` resolves to a constant whose value is ≤ 4 |
| 4 | Frames mode produces N=fps*duration individual PNGs | `./screengrab --duration 2s --fps 2 --mode frames --output out_frames` produces exactly 4 files matching `out_frames/frame_*.png`, each a valid PNG per `file` |
| 5 | Spritesheet mode produces one composite PNG plus sidecar JSON | `./screengrab --duration 2s --fps 2 --mode spritesheet --output out_sheet` produces `out_sheet/spritesheet.png` (valid PNG) and `out_sheet/spritesheet.json` describing rows, cols, frame count, frame size |
| 6 | SIGINT triggers a clean stop and flushes output | Sending SIGINT mid-run leaves a non-empty output directory and exits 0 |
| 7 | A `--gui` flag exists and is documented | `./screengrab --help` exit 0 and stdout contains `--gui` |
| 8 | The GUI uses Wails v3 (not Fyne) | `grep -nE "github.com/wailsapp/wails/v3" gui.go go.mod` returns at least one hit in each; `grep -c "fyne.io" go.mod` returns 0 |
| 9 | The GUI window uses the native macOS Liquid Glass backdrop | `grep -nE "MacBackdropLiquidGlass\|MacLiquidGlass\|NSVisualEffectMaterial\|LiquidGlassStyle" gui.go` returns at least three distinct markers, showing both the backdrop selection and the `LiquidGlass` material configuration block are wired |
| 10 | Capture primitives are exposed as a Wails service | `grep -nE "application\.NewService\(" gui.go` resolves, and the registered service struct defines methods that wrap `captureFrame`/`captureRegion`/`copyFrames` so the frontend can call them across the bridge |
| 11 | `copyFrames` helper is tested round-trip | `go test ./... -run TestCopyFrames -count=1` exits 0 and the test asserts: destination dir created, exactly the selected count of PNGs present, bytes match the source frames |
| 12 | Frontend assets are embedded into the binary | `grep -nE "go:embed" gui.go main.go` returns at least one match pointing at the `frontend/` tree, and the embedded FS is passed to `application.AssetOptions.Handler` |
| 13 | Frontend honours Apple Liquid Glass design rules | `grep -nE "backdrop-filter\|prefers-reduced-transparency\|prefers-reduced-motion" frontend/style.css` returns at least three matches, covering both the material recipe and the accessibility fallbacks |
| 14 | Region selection is region-bounded and bound to the capture service | `grep -nE "func .*captureRegion\(|CaptureRegion\(" *.go` resolves to a signature taking display index plus x/y/w/h ints and returning `(*image.RGBA, error)` |
| 15 | The save action persists selected frames and surfaces the output path | The frontend's save flow calls a Wails-bound method that runs `copyFrames` and returns the resolved destination path to JS so it can be displayed (or copied) without a second round-trip |
| 16 | Frontend / backend method bindings stay in sync | `go test ./... -run TestCaptureServiceBindingsMatchFrontend -count=1` exits 0. The test reflects on `*CaptureService`, parses the `SVC_FQN` constant and every `svc("Method", ...)` call in `frontend/main.js`, and asserts both the FQN prefix and every JS-called method resolve to a real Go method. Prevents the "unknown bound method name" runtime failure that hit the GUI when the JS prefix omitted the `<package>.<struct>` path Wails v3 builds via reflection. |
| 17 | CLI accepts a `--source` flag that addresses either a physical display or a macOS maximized-app window | `./screengrab --help` exit 0 and stdout contains `--source`. `./screengrab --source display:0 --duration 500ms --fps 2 --output out_src` exits 0 and produces at least one PNG. The flag's documented forms are `display:N` (legacy `--display N` still works) and `window:0xHEX` (macOS only). |
| 18 | macOS window enumeration and capture is implemented via CGo against ScreenCaptureKit | `grep -nE "//go:build darwin" mac_capture.go` resolves and `grep -nE "SCShareableContent\|SCContentFilter\|SCScreenshotManager" mac_capture.go` returns at least three hits, with `initWithDesktopIndependentWindow` used to scope capture to one window. The matching `mac_capture_stub.go` carries `//go:build !darwin` and returns an `ErrWindowCaptureUnsupported` sentinel. The pre-15.0 `CGWindowListCreateImage` path was avoided because that symbol is marked unavailable on the macOS 15+ SDK and produces a hard build error. |
| 19 | A unified `Source` type drives both CLI and GUI capture paths | `grep -nE "type Source struct\|func parseSource\(|func listSources\(|func captureSource\(|func captureSourceRegion\(" source.go` returns at least five distinct symbol hits, and the GUI's `StartRecording` calls `captureSource`/`captureSourceRegion` rather than the raw display primitives. |
| 20 | `parseSource` is unit-tested round-trip including the legacy plain-int form | `go test ./... -run TestParseSource -count=1` exits 0. The test covers `display:0`, `window:0x1A`, plain `0` (legacy), and at least two malformed inputs that must produce a non-nil error. |
| 21 | The Wails service exposes `ListSources` and `SnapshotSource` to the frontend | `grep -nE "func \(s \*CaptureService\) ListSources\(|func \(s \*CaptureService\) SnapshotSource\(" gui.go` resolves to both. The frontend in `frontend/main.js` references both via `svc("ListSources")` / `svc("SnapshotSource", ...)` and `go test ./... -run TestCaptureServiceBindingsMatchFrontend -count=1` passes with these additions. |
| 22 | The GUI picker labels macOS maximized-app windows distinctly from displays so the user can tell them apart | `grep -nE "kind\s*===?\s*['\"]window['\"]" frontend/main.js` returns at least one hit (the renderer branches on source kind), and the option label for a window source includes the owning app name in its visible text. |
| 23 | The source list is pruned of XPC / view-service helpers and tags each entry with its on-screen state | `grep -nE "func isHelperApp\(|func isLikelyUserWindow\(|func isFullscreenSpace\(" source.go` returns three hits; the `Source` struct in `source.go` has an `OnScreen bool` field; `./screengrab --list-sources` stdout contains the literal markers `[live` and `[off-Space`. |
| 24 | Recording an off-Space target waits and resumes rather than exiting | `go test ./... -run TestCLI -count=1` exits 0, proving the CLI retries ScreenCaptureKit misses while the target window still exists, resumes to the requested successful-frame count, and fails if the window closes. The GUI continues to emit `capture:frame_error` on skipped frames. |
| 25 | Recording a window source shows a 3-second "switch to the target Space" countdown before capture begins; display sources start immediately | `grep -nE "data-view=\"countdown\"" frontend/index.html` resolves; `grep -nE "function runCountdown\(" frontend/main.js` resolves to a function called from `startRecording` only when `src.kind === "window"`. The countdown view has a Cancel button (`countdownCancelBtn`) wired to abort the wait and return to the setup view. A heads-up element (`#windowHint`) on the setup view also appears only when a window source is selected so the user is warned before clicking Start. |
| 26 | CLI exposes agent-ready controls for bounded captures | `./screengrab --help 2>&1` exits 0 and combined output contains all of: `--json`, `--frames`, `--region`, `--max-dim`, `--format`, `--quality`, `--overwrite`. |
| 27 | Source discovery has a machine-readable shape | `./screengrab --list-sources --json` exits 0 and stdout is JSON with `ok: true`, a numeric `count`, and a `sources` array whose entries use the same `Source` fields as the GUI. No human legend text is emitted in JSON mode. |
| 28 | Capture runs produce a compact JSON summary plus durable manifest | `./screengrab --frames 1 --max-dim 640 --format jpg --quality 80 --json --output out_agent` exits 0, stdout has `ok: true` and `manifest_path`, `out_agent/manifest.json` exists, and the manifest includes generated file paths, dimensions, bytes, source, fps, format, and frame count. |
| 29 | Agent-budget helpers are unit-tested without requiring screen capture | `go test ./... -run 'Test(ParseRegionSpec|PlannedFrameCountCapsDuration|FitToMaxDim|NormalizeConfigFormatAndValidation|WriteImageJPEG|PrepareOutputDirOverwriteGuard)' -count=1` exits 0. |
| 30 | Generated output is overwrite-safe by default | The overwrite guard refuses an output directory containing generated `frame_*`, `spritesheet.*`, or `manifest.json` files unless `--overwrite` is set; `go test ./... -run TestPrepareOutputDirOverwriteGuard -count=1` exits 0. |
| 31 | Microphone recording and transcription are explicit CLI features and remain off by default | `./screengrab --help 2>&1` contains `--microphone`, `--transcript`, and `--transcript-locale`. A normal capture produces no `audio.wav` or transcript files, and `--transcript` without `--microphone` fails validation. |
| 32 | macOS microphone capture and on-device transcription use system frameworks without runtime dependencies | `grep -nE "AVAudioEngine|SFSpeechURLRecognitionRequest|requiresOnDeviceRecognition" mac_audio.go mac_transcript.go` returns all three markers; `go.mod` has no new direct dependency. The matching `mac_audio_stub.go` and `mac_transcript_stub.go` files carry `//go:build !darwin` and return explicit unsupported errors. |
| 33 | Audio-enabled manifests associate frames and timed transcript segments on one media timeline | Capture manifests are version 2; frame entries have `capture_offset_seconds` and `audio_offset_seconds`, the `audio` object describes `audio.wav`, and `transcript.json` contains ordered `start_seconds` / `end_seconds` segments. `go test ./... -run 'Test(NormalizeConfigFormatAndValidation|GeneratedFilePatternsIncludeAudioArtifacts|TimedArtifactValidation)' -count=1` exits 0. |
| 34 | GUI capture exposes microphone/transcript controls and preserves associated artifacts when saving selected frames | `grep -nE "microphoneInput|transcriptInput|reviewArtifacts" frontend/index.html frontend/main.js` finds all controls/states, `go test ./... -run 'Test(CaptureServiceBindingsMatchFrontend|CopySelectedCapturePreservesAssociatedArtifacts)' -count=1` exits 0, and selected output contains audio, transcript, selected frame offsets, and a rewritten manifest. |
| 35 | Packaged macOS apps declare microphone and speech-recognition usage | `make app` exits 0 and `plutil -extract NSMicrophoneUsageDescription raw dist/screengrab.app/Contents/Info.plist` plus the matching `NSSpeechRecognitionUsageDescription` command both return non-empty descriptions. |
| 36 | A `--audio` flag selects the recorded tracks, with `--microphone` kept as an alias | `./screengrab --help 2>&1` contains `--audio` with the documented values `mic`, `system`, `both`. `./screengrab --audio bogus` fails validation before capturing. `go test ./... -run TestNormalizeConfigAudioSelection -count=1` exits 0, covering the alias mapping (`--microphone` → `mic`, `--microphone --audio system` → `both`) and that `--transcript` accepts any audio track. |
| 37 | macOS system-audio capture uses ScreenCaptureKit's audio stream, scoped to the capture source | `grep -nE "SCStream\|capturesAudio\|SCStreamOutputTypeAudio" mac_system_audio.go` returns all three markers, the filter uses `initWithDesktopIndependentWindow` for window sources and `initWithDisplay` for display sources, and `go.mod` gains no new direct dependency. The matching `mac_system_audio_stub.go` carries `//go:build !darwin` and returns an explicit unsupported error. |
| 38 | System-audio manifests stay frame-aligned and survive selected-frame export | Frame entries and the frame timeline carry `system_audio_offset_seconds` next to `audio_offset_seconds`; the manifest describes `system_audio.wav` under `system_audio` and its transcript under `system_transcript`. `go test ./... -run 'Test(TimedArtifactValidation|GeneratedFilePatternsIncludeAudioArtifacts|CopySelectedCapturePreservesAssociatedArtifacts)' -count=1` exits 0. |

Non-goals: per-application audio mixing or device selection, speaker diarization, cursor visibility toggling, full Linux/Windows verification (best-effort via `kbinani/screenshot` cross-platform backends; the Wails frontend falls back to the CSS Liquid Glass recipe on Chromium-family webviews and to a solid surface where transparency is denied). macOS is the verified target.

Permission note: on macOS the first screen capture prompts for Screen Recording permission. System-audio recording rides that same permission — ScreenCaptureKit's audio stream never triggers a separate prompt. Opting into microphone recording and transcription additionally prompts for Microphone and Speech Recognition access. Audio/transcription denial fails before the first frame; silent capture never requests those permissions.
